# floortint v3 — 平面図から「平面着色」を自動生成する（Streamlit）

レイアウト平面図の PDF を入れると、床に床材の模様（タイルカーペット、塩ビタイル、木目、または登録した実物写真）を貼った
「平面着色」を作ります。家具は白のまま影を付け、寸法線・通り芯・席マーカー・人物は消し、室名と植栽は残します。
Photoshop で範囲ごとに床材画像を貼っていた作業の全自動化が目的です。

着色の根拠は 3 通りから選べます。

| モード | 入力 | 動き |
| --- | --- | --- |
| 床仕上図から（自動） | 平面図 + 床仕上図 | 床仕上図の凡例と色別ハッチ・貼り方向の矢印を読み、全自動で塗る |
| 指示書から（手書き・塗り） | 平面図 + 指示書（PDF / PPTX / PNG / JPG） | PPT の塗り図形・iPad の手書き・マーカーの色を平面図の部屋に重ねて割り当てる。PPT の凡例（品番・メーカー・貼り方・写真・リンク）は自動で読む |
| 指示なし（手動で割り当て） | 平面図 | 部屋ごとに画面で材種を割り当てる（図をクリック、または表） |

v2 で追加: PDF のレイヤー名による図面整理（寸法・通り芯・ワークポイント・人物・文字を確実に落とし、転用什器は残す）、指示書モード、
手動モード、床材の写真ライブラリ、植栽・躯体の扱い（元のまま／指定色／消す）、レイヤー分けの書き出し（ZIP）、物件ごとの設定の保存・読込。

v3 で追加（2026-10-16）: **PPT 指示書**（貼った図面画像の実データで位置合わせ、塗り図形・凡例・矢印・製品写真・リンクを読む。PPTX を直接入れられる）、
**iPad 手書き指示書**（図面 PDF に描き足した斜線ハッチ・囲みを面にし、引出線・文字・写真は「吹き出し」として部屋に紐づける）、
**コア・共用部を塗らない既定**（EV・階段に加えて WC・PS・EPS・機械室・湯沸室などを室名で判定）、**後編集**（部屋をクリックして材種／塗らない、
2 点クリックの線で部屋を分けて張り分け、矩形で上書き。頂点編集は無し）、**OA 割付のマス目の除去**（等間隔の直線群とレイヤー名）、
**縮尺の手動指定**、**ライブラリの裏蓄積**（指示書の品番・写真を自動登録し、同じ品番が出たら自動で当てる。最終使用日・廃盤フラグ・製品ページのリンク・
材種セットの ZIP 書き出し／読み込み）。

外部 API や GPU は使いません。PDF の解析・描画（pypdfium2 = Google pdfium、BSD-3 / Apache-2.0）と画像処理（OpenCV）だけで完結します。AGPL のライブラリ（PyMuPDF）は v3.1 で外しました（`python run_cases.py --check-deps` で確認できます）。

## 入力の前提

| 条件 | 内容 |
| --- | --- |
| PDF の形式 | CAD から出力したベクタ PDF（文字とパスを持つもの）。スキャン画像の PDF は対象外 |
| 床仕上図の描き方 | 材種ごとに色の違うハッチ線で塗り範囲を描き、凡例表の記号欄に同じ色のハッチ小片、右隣に仕様（品番／メーカー／寸法／貼り方）を書く方式 |
| 貼り方向 | 黒塗りの両矢印（三角＋軸） |
| 平面図と床仕上図 | 同じ CAD データ由来で縮尺が同じこと。通り芯ラベル（X1…/Y1… または丸付き番号）で自動的に重ねる |
| 図面帳 | 竣工図書・基本設計図書のような複数ページの PDF でも可。表題欄の「図面名称」からページを自動で特定する |

| レイヤー | CAD から出した PDF のレイヤー（寸法・通り芯・WP・人物・文字・植栽・躯体・什器）があれば、それで図面を整理する。無ければ色・線種で整理する |
| 指示書 | (a) PPT（PPTX または PDF 書き出し。図面の画像を貼り、半透明の図形で範囲を示し、色見本＋品番／メーカー／貼り方＋製品写真の凡例があるもの）、(b) 図面 PDF に iPad で描き足した手書き（斜線ハッチ・囲み・引出線＋文字・写真）、(c) ベクタ PDF の半透明マーカー、(d) 画像（スクリーンショットに塗ったもの）。手書きの品番は読まない（PDF に認識文字が埋まっていればそれを表示） |

参照した 6 案件（床仕上図あり）と 17 案件（指示書あり／なし。PPT 10・手書き 1・ベクタ 2・画像 2・なし 2）で人手なしに通ることを確認しています。

## 画面の使い方

1. 左ペインで「着色の根拠」を選び、「PDF をアップロード」で平面図の PDF（と床仕上図 PDF または指示書）を入れる
   （図面帳なら 1 つのファイルで両方を指定でき、ページは自動で選ばれる。選び直しも可）。
2. 数秒〜数十秒で右に着色結果が出る。上段の 6 項目（縮尺、図面の整理、位置合わせ／部屋数、材種数／指示書の色数、
   領域数／指示書の位置合わせ、家具）で自動読み取りの結果を確認する。
3. 「レイヤー」で落とす／残す層を確認する（既定で自動）。
4. 指示書・手動モードでは「📋 材種と割り当て」で材種を定義し（PPT の凡例があれば品番・メーカー・貼り方・写真が入っている。無ければ名前・種類・
   貼り方・寸法・色を入れるか写真ライブラリから選ぶ）、指示書の色 → 材種を対応づける。「部屋ごとの割り当て（後編集）」で図をクリックして
   材種／塗らない、2 点クリックの線で部屋を分けて別の材種（共用部と専有部の張り分け）、矩形で上書きができる。指示の無い部屋の材種（または塗らない）も選べる。
   コア（EV・階段）と共用部（WC・PS・機械室など室名で判定）は既定で塗らない（左ペインで変えられる）。手書きの吹き出し（文字・写真）は紐づいた部屋と一緒に表示される。
5. タブで確認・調整し、書き出す。

| タブ | 内容 |
| --- | --- |
| 🎨 着色結果 | 完成画像と部分拡大 |
| 🔍 検証 | 床仕上図モード: 復元領域を凡例の色で重ねた図と貼り方向。指示書・手動モード: 部屋の塗り分けと指示書の色、塗った単位の表。家具の足元 |
| 📋 材種と割り当て | 材種の定義・色・拡大率・貼り方・写真。領域／部屋ごとの上書き |
| 🗂 床材ライブラリ | 製品ごとに実物写真（1〜6 枚。1 枚 = タイル 1 枚・板 1 枚）を登録。指示書の凡例から品番・写真・リンクを自動で蓄積（最終使用日・案件数）。廃盤フラグ、材種セットの ZIP 書き出し／読み込み |
| 🛠 処理の内訳（デバッグ） | 段階ごとの時間・指標・途中画像（レイヤー一覧、部屋、指示書の位置合わせを含む） |
| 💾 書き出し | PNG（300dpi）／PDF／抽出結果 JSON／レイヤー分け ZIP（床・影・家具・躯体・線画・植栽・文字の透過 PNG） |

左ペインの調整項目は既定値で全自動になるように決めてあり、好みで変えられます。模様の見かけの大きさ（既定 600mm）、
目地の濃さ、木目・毛並み、影の長さ・ぼかし・濃さ、家具とみなす面積、植栽・躯体の扱い、線画の濃さ、室名の有無、
既存床の扱い、出力解像度、位置合わせの手動補正、指示書の読み取り（彩度の下限、無視する塊、割り当ての閾値）、図面整理の各規則などです。
左ペイン下の「物件の設定を保存・読込」で、これらと材種の対応・部屋の上書きを物件名で保存できます（保存先は環境変数 `FLOORTINT_LIBRARY`）。

## 処理の流れ

```
[1] 取込        表題欄から図面名称・縮尺。ページ種別の判定
[2] 位置合わせ  通り芯ラベルの同名対応で平行移動量。無ければ画像の相関        （床仕上図モード）
[3] 凡例        記号の色 → 仕様（材種／品番／メーカー／寸法／貼り方／備考）    （床仕上図モード）
[4] 領域        色別ハッチ線をラスタ化 → 閉じる → 材種の重なりを解決 → 壁の黒線に沿わせる → 輪郭（床仕上図モード）
[5] 方向        黒塗り矢印 → 角度 → 内包する領域へ                              （床仕上図モード）
[6] 図面整理    レイヤー名（無ければ色・線種）で寸法線・通り芯・席マーカー・人物・文字を除外し、壁・家具・建具・植栽・躯体だけに
[7] 家具        線で囲まれた小さな閉領域 ＋ 椅子の記号の凸包 を家具の足元に
[9] 部屋        線画の閉領域から部屋を取る（EV・階段はコアとして既定で塗らない）  （指示書・手動モード）
[10] 指示書     PPT: 図面画像の実データで位置合わせ → 塗り図形・凡例・矢印を読む／手書き: ハッチ・囲みを面に、引出線と文字・写真は吹き出し／
                マーカー・画像: 従来。色の塊を平面図に重ね、輪の内側・塗りつぶし・線で区切った区画として部屋に割り当てる（指示書モード）
[8] 合成        床の模様（生成 or 写真）→ 既存床 → 影 → 家具の白 → 躯体 → 線画 → 植栽 → 室名
```

## ファイル構成

```
floortint/
├─ app/
│  ├─ app.py                 # Streamlit 画面
│  ├─ run_cases.py           # サンプル案件の一括処理（FLOORTINT_SAMPLES / FLOORTINT_SAMPLES2 に PDF があるときだけ動く）
│  ├─ evaluate.py            # 指示書・手動モードの案件をデザイナー出力と比べる
│  ├─ floortint/
│  │  ├─ pdfio.py            #   PDF の読み取り層（pypdfium2。図形・文字・描画・画像・リンク）
│  │  ├─ pdfdoc.py           #   取込・ページ種別・縮尺・位置合わせ
│  │  ├─ layers.py           #   PDF のレイヤー名の分類（落とす／植栽／躯体／残す）
│  │  ├─ legend.py           #   凡例の読み取り
│  │  ├─ regions.py          #   塗り領域の復元・重なり解決・黒線への吸着・貼り方向
│  │  ├─ cleanplan.py        #   図面の整理と家具の足元
│  │  ├─ rooms.py            #   部屋（閉領域）、コア・共用部の判定、線での分割
│  │  ├─ instruct.py         #   指示書の読み取り（ベクタ／ラスタ）、位置合わせ、部屋への割り当て
│  │  ├─ library.py          #   床材の写真ライブラリと物件設定の保存
│  │  ├─ textures.py         #   床模様の生成（流し／市松／乱／アシュラー／ブリック／ヘリンボーン）と写真貼り
│  │  ├─ compose.py          #   合成（植栽・躯体の扱い、レイヤー分け）
│  │  ├─ pipeline.py         #   入口。段階ごとの記録
│  │  ├─ quality.py          #   精度指標
│  │  └─ debugview.py        #   デバッグ表示の補助
│  └─ samples/               # サンプル案件の置き場（空。社内限の図面はここに置かない限り同梱されない）
├─ Dockerfile
├─ entrypoint.sh
├─ requirements.txt
├─ .env.example
├─ README.md / README.pdf
└─ DEPLOY_AZURE.md / DEPLOY_AZURE.pdf
```

## ローカルでの起動

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
# 室名の描画には IPA P ゴシックが要る（Debian/Ubuntu: apt install fonts-ipafont-gothic）
# PPTX の指示書を直接入れるには LibreOffice が要る（apt install libreoffice-impress）。無ければ PPT を PDF に書き出して入れる
cd app && streamlit run app.py --server.port 8000
```

Docker で動かす場合:

```bash
docker build -t floortint:v3 .
docker run --rm -p 8000:8000 -v $(pwd)/library:/app/library floortint:v3   # library/ に写真と設定を残す
```

## 制約と既知の課題

- 品番の実物の色は持ちません。材種ごとの既定色（カーペットはグレー系、塩ビ・木は木目色）を画面で差し替える運用です。
- 床仕上図が「色別ハッチ線」の規約で描かれていることが前提です。塗りつぶしで描かれた図面やスキャン画像は未対応です。
- 椅子の記号は CAD ライブラリごとに形が違います。曲線を含まない折れ線だけの椅子で背が大きく開いたものは線だけが残ります。
- 短い線分で描かれた曲線の区画は「壁の黒線に沿わせる」処理の境界にならず、閉じたマスクの輪郭のままになります（見た目には影響しません）。
- 8pt 前後の大きな記号（壁種の「65」など）は文字サイズを超えるため残ります。
- レイヤー名の分類は語の一致です。見たことのない命名（建物側 CAD の「1-STB3」など）は「残す」になります。画面の一覧で反転できます。
- 部屋は線画の閉領域です。外壁や間仕切りの線に切れ目があると部屋になりません（「線の切れ目を埋める幅」を上げる）。
- 指示書の色の意味（輪＝内側、線＝境界、塗り＝その範囲）は形から推定します。外れたときは色ごとの「割り当て方」と部屋ごとの上書きで直します。
  手書きの品番は読みません（吹き出しとして画像で表示）。共用部は室名の語で判定するので、室名の無い図面では塗られます（クリックで外す）。
- PPT 指示書は「図面の画像を貼ったスライド」が前提です。図面が WMF などのベクタで貼られたスライドは、そのスライドの PDF を平面図としても使えば動きますが未検証です。
  凡例は「色見本の右か下に文字」の配置を想定しています。製品ページのリンク先は開きません（URL を表示するだけ）。
- 外部の床材サイト（TECTURE、Material Bank）との連携はしていません（前者は一覧がスクリプト描画で規約確認が要り、後者は自動アクセスを拒否します）。
- 画像の指示書の位置合わせは線画の相関で、回転は扱いません。相関が弱いときは警告が出るので手動補正を使います。

## 処理時間の目安

| 図面 | 縮尺 | 材種 | 抽出 | 合成（300dpi） |
| --- | --- | --- | --- | --- |
| 単フロアのレイアウト（A3） | 1/200 | 6 | 2〜3 秒 | 1.5 秒 |
| 図面帳 58 ページ中の 2 ページ | 1/300 | 14 | 14 秒 | 3.5 秒 |
| 指示書モード（A3、半透明マーカーの PDF） | 1/200 | 7 色 | 16 秒 | 4.6 秒 |
| 指示書モード（A3、画像の指示書、図形 21 万） | 1/150 | 8 色 | 35 秒 | 7.2 秒 |
| 指示書モード（A3、PPT。図面画像の位置合わせ＋凡例） | 1/150 | 7 色 | 4〜13 秒（PPTX の変換に別途 10〜20 秒） | 3〜5 秒 |
| 指示書モード（A3、iPad 手書き） | 1/200 | 4 色 | 5 秒 | 3 秒 |

抽出はファイルごとにキャッシュされ（最大 3 件）、色や倍率の変更では合成だけが走ります。
メモリは 300dpi の A3（約 17M 画素）で 1.5〜2GB 程度、指示書モードは部屋・色の塊を持つため 1 件あたり 0.5GB 程度増えます。

## セキュリティ

- 図面はサーバのメモリ上でだけ処理し、ディスクに保存しません。ログにも図面の内容を出しません。
  例外は床材ライブラリ（登録した写真）と物件設定（材種の対応・部屋の上書き・数値。図面は含まない）で、`FLOORTINT_LIBRARY` 配下に残ります。
- 外部との通信はありません（フォント・モデルのダウンロードも無し）。
- アプリ自体にログイン機能はありません。社内限の図面を扱うので、App Service の認証（Entra ID）か
  閉域構成で運用してください（DEPLOY_AZURE.md 参照）。
